## 一、架构

```
┌─────────────────────────────────────────────────────────────┐
│  Android App 进程 (com.hydrogen.music)                       │
│                                                             │
│  ┌────────────────────────┐      ┌───────────────────────┐  │
│  │  WebView               │      │  Node 运行时 (libnode) │  │
│  │  页面: https://localhost│      │                       │  │
│  │  （前端 dist 产物）     │      │  ① 内置网易云 API      │  │
│  │                        │      │     127.0.0.1:36530    │  │
│  │  axios baseURL =       │      │          ▲            │  │
│  │  http://127.0.0.1:36531│─────▶│  ② CORS 转发层         │  │
│  └────────────────────────┘      │     127.0.0.1:36531   │  │
│              │                   └───────────────────────┘  │
└──────────────┼──────────────────────────────────────────────┘
               ▼
        屏幕 / 扬声器            （转发层再访问 music.163.com）
```

**为什么多一层转发（36531）**：上游 API 不带 CORS 头，而 WebView 页面在
`https://localhost`，跨域。又因为 `serveNcmApi()` 返回时已经 listen 完成，没法再
往它的路由链前挂中间件，所以单独起一层转发最可控。这层还负责清掉上游 `Set-Cookie`
的 `Domain`/`Secure`，否则 WebView 存不下。

**三种运行形态**（同一份 `src/`）：
| 形态 | API 来源 | 前端请求地址 |
|---|---|---|
| 桌面 Electron | 主进程内置 | 经 preload 走 IPC |
| 手机浏览器 | 电脑上起的 API | 同源 `/api`（本地服务反代） |
| **Android APK** | **App 内嵌 Node** | `http://127.0.0.1:36531` |

分流在 `src/utils/request.js` 的 `resolveApiBaseURL()`，靠构建时注入的
`window.__HM_APP__` 标记判断（比探测 `window.Capacitor` 更稳）。

## 二、Android 专属的坑（PC 上一个都不会触发）

> **核心教训：PC（Node 22）跑通 ≠ 手机（Node 18 + small-icu）能用。**
> 下面 8 条全部只在真机暴露。

### 坑 1 · Node 直接崩
- **现象**：`Cannot find module '.../pac-proxy-agent/dist/index.js'`；或 APK 里
  `libnode.so` 体积为 0
- **根因**：依赖被安全机制改名成 `.DELETE.<hash>`；`app/capacitor.build.gradle` 丢失
  导致 `implementation project(':capawesome-capacitor-nodejs')` 缺失，`libnode.so` 没编进去
- **检查**：APK 内必须有 `lib/{arm64-v8a,armeabi-v7a,x86_64}/libnode.so`

### 坑 2 · `/tmp` 不可写
- **现象**：`EACCES: permission denied, open '/tmp/anonymous_token'`，API 启动即挂
- **根因**：Android 没有可写的 `/tmp`。**插件虽然设了 `TMPDIR` 环境变量，但实测
  Node 的 `os.tmpdir()` 仍返回 `/tmp`**（诊断日志：`os.tmpdir()=/tmp | TMPDIR=.../cache`）
- **修法**：`mobile-runtime/index.js` **顶部**（必须在 require API 之前）主动改写
  `os.tmpdir`。按 `require('bridge').app.datadir()` → `TMPDIR/TMP/TEMP/HOME` 顺序
  探测可写目录（`mkdir -p` + 写探针文件），选中后 `os.tmpdir = () => dir` 并同步环境变量

### 坑 3 · `\p{...}` 不被支持
- **现象**：`Invalid regular expression: /^[$_\p{ID_Start}]$/: Invalid property name in character class`
- **根因**：**nodejs-mobile 内嵌的 Node 是 small-icu 构建**，缺 Unicode 属性表。
  命中 `path-to-regexp`（Express 路由依赖，启动必加载）
- **修法**：`scripts/patch-path-to-regexp.cjs` 改成 ASCII 等价写法
  （`\p{ID_Start}`→`A-Za-z`，`\p{ID_Continue}`→`A-Za-z0-9`），构建时自动执行

### 坑 4 · 启动竞态（"进去像连不到网"）
- **现象**：首批请求全部 `AxiosError: Network Error`
- **证据**：前端 `13:55.776` 发请求报错，Node `13:57.728` 才就绪 —— **差 2 秒**
- **根因**：WebView 立刻加载并发请求，内嵌 Node 冷启动要 ~2.5s 才监听端口，
  且前端不重试
- **修法**：`src/utils/request.js` 的 `ensureNcmApiReady()` 原来只对桌面端生效
  （原生 App 直接 skip），为原生 App 加分支：用 XHR 轮询
  `http://127.0.0.1:36531/__hm_ready`，拿到任意 HTTP 响应（含 404/502）即放行，
  最长等 20s，只跑一次

### 坑 5 · 歌能看不能播
- **现象**：`[ERROR] /song/url/v1?... { status: undefined, body: undefined }`
- **根因**：该接口走 **xeapi** 加密，`util/request.js` 的 xeapi 分支需要
  `<tmpdir>/xeapi_public_key`，缺失即 `throw new Error('xeapi public key is missing')`。
  该文件由 API 包的 `generateConfig.js` 生成，**官方入口 `app.js` 会在启动 API 前
  `await generateConfig()`，自写的运行时入口很容易漏掉这一步**
- **修法**：`mobile-runtime/index.js` 的 `prepareNcmConfig()`，在 `startNcmApi()`
  之前先确保 `anonymous_token` 文件存在，再 `require('@neteasecloudmusicapienhanced/api/generateConfig')()`

### 坑 6 · `localhost` vs IPv6
- 运行时只监听 IPv4 `127.0.0.1`，而 Android 上 `localhost` 可能优先解析到 `::1`
- **修法**：`NATIVE_APP_API_BASE` 写死 `http://127.0.0.1:36531`，不要用 `localhost`

### 坑 7 · 通知栏按钮点不动（★ 最隐蔽）
- **现象**：通知栏卡片显示正常（歌名/歌手/三个按钮都在），但**点按钮毫无反应**
- **关键陷阱**：**媒体键有效 ≠ 通知栏按钮有效**，这是两条不同的路：
  - `adb shell input keyevent 127` → `MediaSession.Callback.onMediaButtonEvent()` → `onPause()` ✅
  - 通知栏按钮点击 → 系统 UI 的 `MediaController.transportControls` → `onPause()` ❌
  **只测媒体键会得出"链路正常"的错误结论。**
- **根因**：MediaData 里 **`mediaId=null`**，MIUI 的媒体卡片拿不到曲目标识，
  就没法给按钮接线；同时它的灵动岛代码会抛
  `NullPointerException: null receiver @ MiuiIslandMediaControllerImpl.addDynamicIslandView`
- **修法**：给 MediaMetadata 补上
  ```java
  .putString(MediaMetadata.METADATA_KEY_MEDIA_ID, songId)   // ← 关键，必须有值
  .putLong(MediaMetadata.METADATA_KEY_DURATION, durationMs)
  ```
  前端 `show()` 相应多传 `mediaId`（曲目 id）与 `duration`
- **附带**：**大图标必须是真正的 Bitmap**。只给资源 id 时系统侧拿到
  `Icon(typ=RESOURCE)`，MIUI 会崩；拿不到封面就用 `Bitmap.createBitmap` + `Canvas`
  把应用图标绘成位图兜底

### 坑 8 · 退后台通知消失
- **根因**：前台服务的存活被**绑在 `playing` 上**，一暂停（或任何状态抖动）就
  `stopService`，通知一起消失，用户再从通知栏按播放就没得按
- **证据**：按 HOME 后 `dumpsys activity services` 里服务数 = 0
- **修法**：**服务只跟"有没有曲目"走**（`visible`），只有 `hide()`（没有曲目了）才停
- **还需要的配套**（已做）：
  1. `mediaSession.setFlags(FLAG_HANDLES_MEDIA_BUTTONS | FLAG_HANDLES_TRANSPORT_CONTROLS)`
     —— 很容易漏，不声明系统不会把媒体键转过来
  2. manifest 加 `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PLAYBACK`，
     以及 `<service android:foregroundServiceType="mediaPlayback" />`（Android 14+ 必需）

## 三、移动端 UI 的坑

> 所有移动端调整集中在 `src/assets/css/mobile.css`，规则统一用
> `html[data-hm-mobile='true'] #app ...` 前缀（`#app` 是为了压过组件的 scoped 样式
> 的优先级）。**原则：不改组件内部样式，桌面端零影响。**

### 3.1 `pointer-events` 与"点击被吃掉"
- 移动端把 `.home-header` 设成 `pointer-events: none`（整条导航让位给底部 Tab），
  **子元素必须显式 `pointer-events: auto`** 才能点
- 更隐蔽的是**兄弟元素吃掉点击**：顶栏 `.globalWidget` 是
  `position: fixed; left:0; right:0` **铺满整条**，它的（哪怕半透明的）底色会盖住
  右上角头像。**视觉上头像是可见的**（顶栏底色透明），但点击全被拦。
  - 实测 `document.elementFromPoint(头像中心)` 返回的是 `DIV.widget-search`
  - **解法**：让顶栏给头像让位，而不是继续调 z-index
    ```css
    .globalWidget { right: 0; pointer-events: none; }   /* 背景铺满但不吃点击 */
    .globalWidget > * { pointer-events: auto; }         /* 交互交给子元素 */
    .widget-search { margin-right: 46px; }              /* 搜索框右侧给头像留位 */
    ```
- **验证手段**：`elementFromPoint` 或 `adb shell input tap`（真实触摸）。
  **合成 `dispatchEvent(new MouseEvent('click'))` 会绕过命中测试**，
  所以"手写 click 能成功、真机手指点却没反应"是这类问题的典型特征

### 3.2 相对描述要先把完整顺序列出来
用户说"倒数两个""右边那两个"时，**必须先把该行的完整元素顺序 grep 出来**再动手。
本次因为没做这一步，把"播放模式按钮右边的两个"改成了"左边的两个"，白改一轮。

`.song-control` 那一行的真实顺序：
```
添加MV → 罗马音 → 翻译(中文) → 原文 → 喜欢 → 订阅电台 → 下载
      → 添加到歌单 → 显示专辑 → 播放模式(随机等) → 歌词/评论切换 → 桌面歌词
```

### 3.3 布局：桌面双栏 → 手机单栏
- `MyMusic.vue` 桌面是「左栏 262px 列表 + 右栏详情」并排。移动端 `flex-direction: column`
  后变成**上 46vh 列表 + 下详情**，于是"点歌单只出半屏"。
  修法：详情路由时给 `.my-music` 加 `has-detail` 类，隐藏左栏、详情占满
- 播放页各行顺序（真机实测 406×904）：
  ```
  topbar          41.. 85
  player-cover    99..635    ← 封面（垂直居中：上/下留白各 ~283）
  player-info    639..722
  hm-player-wave 724..754    ← 波形
  song-control   770..794    ← 歌词开关那一行（桌面是竖排 column+gap:3vh，
                                手机必须改 flex-direction: row，否则撑到 376px 高）
  player-control 796..904
  ```

### 3.4 波形（音乐可视化）取不到音频
- **真机实测 `currentMusic` 内部**：
  ```json
  { "howlContext": false, "howlGain": false,
    "nodeType": "[object HTMLAudioElement]",   // Howler 退化成 HTML5 音频模式
    "hasBufferSource": false, "hasAnalyser": false }
  ```
- Howler 在移动端不走 Web Audio，唯一剩下的分析路径是 `captureStream()`；
  而网易云音频来自跨域 CDN 且**不带 CORS 头** → 拿不到音频轨道 → 分析器永远挂不上
- **修法**：给组件加 `forceVisible` prop，在拿不到真实频谱时用**合成包络兜底**
  （`buildSyntheticLevels()`），至少正确表达"正在播放/已暂停"。桌面端不受影响
- 想要真实频谱，只能把音频也走本地转发层 + 加 `Access-Control-Allow-Origin`，
  再配 `Howler.crossOrigin='anonymous'`（改动较大，未做）

### 3.5 深色模式
`mobile.css` 原本只有 2 条 `.dark` 规则，组件的 scoped 样式又多以浅色为底 → 大片露白。
已按 `theme.css` 的变量（`--bg / --text / --layer / --panel / --border`）补了一整块覆盖。
注意：播放页组件自带**浅蓝渐变底**，深色下要 `background-image: none` 盖掉。

## 四、看不见截图时怎么定位问题

本次模型无法读图片，改用**像素分析 + 坐标映射**，效果意外地好：

```python
# 用 PIL + numpy 找用户标注（鲜红）与可疑 UI 色块，输出相对坐标
red    = (R > 150) & (G < 95)  & (B < 95)  & (sat > 75)
orange = (R > 185) & (G > 75)  & (G < 195) & (B < 120) & (sat > 65)
```
截图与视口比例一致时（如 864×1919 对 406×904），可直接按比例映射到 CSS 坐标，
再配合 `elementFromPoint` 问出"这个位置到底是什么元素"。

**实测案例**：用户圈出的红色标注带在 `y 1632-1679` → CSS `y 769-791`，
正好落在 `.song-control`（770..794）上，据此确认用户圈的就是那一行图标。

## 五、验证方法学（最重要的一节）

**这个项目最大的教训是：不要凭代码推断，要真机实测。**

1. **PC 上跑通不代表手机能用** —— 上面 8 个坑 PC 一个都不触发
2. **不同触发路径要分别验证** —— 媒体键 vs 通知栏按钮就是典型反例
3. **合成事件会骗人** —— `dispatchEvent` 绕过命中测试，必须用 `input tap`
4. **原生日志比 console.log 可靠** —— 后者要 `loggingEnabled` 才进 logcat
5. **看数据，别看现象** —— "通知栏不能用"最终定位到 `mediaId=null` 这个具体字段
