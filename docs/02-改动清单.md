## A. 核心逻辑

### A1. `mobile-runtime/index.js` ⭐ 内嵌 Node 运行时入口
整个 App 的启动核心：启动 36530 API + 36531 转发层。

| 改动 | 原因 |
|---|---|
| **顶部改写 `os.tmpdir`**（在 require 任何 API 之前） | Android 没有可写的 `/tmp`。插件设的 `TMPDIR` 无效（`os.tmpdir()` 仍返回 `/tmp`）。按 `require('bridge').app.datadir()` → `TMPDIR/TMP/TEMP/HOME` 顺序探测可写目录 |
| **新增 `prepareNcmConfig()`**，在 `startNcmApi()` 前调用 | 官方入口 `app.js` 会先 `await generateConfig()` 生成 `anonymous_token` 与 `xeapi_public_key`；自写入口漏了这步会导致 `/song/url/v1`（走 xeapi）报 "public key is missing"，表现为**歌能看不能播** |

### A2. `src/utils/request.js`
| 改动 | 原因 |
|---|---|
| `ensureNcmApiReady()` 增加**原生 App 分支** | 原逻辑只对桌面端生效（原生 App 直接 skip）。WebView 立刻发请求，而 Node 要 ~2.5s 才监听端口，且前端不重试 → 首批请求全部 Network Error。改为用 XHR 轮询 `127.0.0.1:36531/__hm_ready`，拿到任意 HTTP 响应即放行，最长 20s，只跑一次 |

### A3. `src/utils/mediaSession.js`
| 改动 | 原因 |
|---|---|
| 新增导出 `initNativeMediaNotification()` | 原文件里的 `initMediaSession()` 走的是 **Web 标准 `navigator.mediaSession`**，但**实测 Android WebView 完全没有这个 API**（`mediaSession`/`MediaMetadata`/`Notification` 全是 undefined），所以 Web 那条路在 App 里是死路，必须走原生插件 |
| `show()` 多传 `mediaId` 与 `duration` | **通知栏按钮点不动的根因**：mediaId 为空时 MIUI 的媒体卡片不给按钮接线 |

### A4. `src/App.vue`
| 改动 | 原因 |
|---|---|
| `onMounted` 里调用 `initMediaSession()` 与 `initNativeMediaNotification()` | `initMediaSession` 一直存在但**全工程从没被 import 过**（死代码），所以通知栏从未生效；原生那条是新接的 |

### A5. `android/app/src/main/java/com/hydrogen/music/MediaNotificationPlugin.java` 🆕
**新增**。安卓通知栏 / 锁屏的媒体控制。

- 只用**框架自带 API**（`Notification.MediaStyle` + `android.media.session.MediaSession`），
  **不引入 androidx.media** —— 因为本项目不跑 `cap sync`，加依赖很麻烦
- 导出 `show({title,artist,album,coverUrl,playing,mediaId,duration})` / `setPlaying({playing})` / `hide()`
- 通知按钮用**运行时注册**的 `BroadcastReceiver`（API 33+ 传 `RECEIVER_NOT_EXPORTED`）
  + `PendingIntent.getBroadcast`，**不用改 manifest 加 receiver**
- 点击后 `notifyListeners('mediaAction', {action}, true)` 回传前端（keepAlive）
- **全程 try/catch**：通知属于锦上添花，绝不能让初始化异常把 App 拉崩
- **大图标必须是 Bitmap**：拿不到封面就用 `Bitmap.createBitmap` + `Canvas` 把应用图标
  绘成位图兜底（只给资源 id 会让 MIUI 拿到 `Icon(typ=RESOURCE)` 并崩）
- `MediaMetadata` 必须带 `METADATA_KEY_MEDIA_ID` 与 `METADATA_KEY_DURATION`
- `mediaSession.setFlags(FLAG_HANDLES_MEDIA_BUTTONS | FLAG_HANDLES_TRANSPORT_CONTROLS)`

### A6. `android/app/src/main/java/com/hydrogen/music/MediaPlaybackService.java` 🆕
**新增**。媒体播放前台服务（`foregroundServiceType="mediaPlayback"`）。

只用 `NotificationManager.notify` 发通知的话，App 一退后台系统就可能回收进程，
通知和播放一起被掐。通知对象由插件构建后放静态字段（同进程）传给服务，服务
`startForeground` 把它挂住。

**注意**：服务只在"**当前有曲目**"时存活（`visible`），**不跟随播放/暂停**。
绑在 `playing` 上的话，一暂停就被 `stopService`、通知一起消失（实测按 HOME 后服务归零）。

### A7. `android/app/src/main/java/com/hydrogen/music/MainActivity.java`
| 改动 | 原因 |
|---|---|
| `onCreate` 里 `registerPlugin(MediaNotificationPlugin.class)` | **必须在 `super.onCreate()` 之前**。本地插件用 `registerPlugin` 比写进 `capacitor.plugins.json` 更可靠 |

### A8. `android/app/src/main/AndroidManifest.xml`
| 改动 | 原因 |
|---|---|
| `POST_NOTIFICATIONS` | Android 13+ 弹通知需要（媒体通知通常免授权，显式声明更稳） |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | 前台服务所需 |
| `<service android:name=".MediaPlaybackService" android:foregroundServiceType="mediaPlayback" />` | **Android 14+ 必需** |

### A9. `scripts/patch-path-to-regexp.cjs` 🆕
把 `path-to-regexp` 里的 `\p{ID_Start}` / `\p{ID_Continue}` 换成 ASCII 等价写法。
原因：nodejs-mobile 内嵌 Node 是 **small-icu** 构建，不支持 Unicode 属性转义，
而这是 Express 路由的依赖、启动必加载。由 `build-android.cjs` 的 `copyRuntime()` 自动调用。

### A10. `scripts/sync-to-build.cjs`
| 改动 | 原因 |
|---|---|
| `NEVER_SYNC` 增加 `cdp-profile`、`mobile-test/*.png`、`docs/`、`README.md` 的同步 | CDP 测试会在 `scripts/mobile-test/` 下生成 **54MB/862 文件**的 Edge 用户数据目录，曾被同步进构建目录（同步数从 290 暴涨到 1161）。**注意不能简单排除所有 `*.png`** —— `src/assets/` 里的图标是真实资源 |

### A11. `.gitignore`
补上 `scripts/mobile-test/cdp-profile/` 与 `scripts/mobile-test/*.png`。

### F2. 踩到的坑（★ 后人也一定会踩）

**`theme.css` 有一条全局带 `!important` 的深色规则：**
```css
.dark button { background-color: #2a2e34 !important; color: var(--text) !important; }
```

第一版滑轨的格子用了 `<button>`，于是在深色下：
- 格子被刷成**不透明深色**（`rgb(42,46,52)`），盖住了 `z-index:0` 的滑块
- 结果整条滑轨只剩「小 中 大」三个字，**完全看不出选中的是哪一格**（浅色下正常，所以只看浅色会漏掉）
- 更隐蔽的是：`getComputedStyle` 查滑块本身仍返回正确的白色 —— **查滑块查不出问题，必须查格子的背景**

**修法**：格子改用 `<div>`。本页同类控件（`.toggle` / `.button` / `Selector` 选项）本来也都是 `div`，
既避开这条全局规则，也更贴合既有写法。

**另一处同类坑（本轮顺手修）**：本项目 `reset.css` **没有重置 `border-radius`**，
所以任何 `<button>` 都会带 UA 的 2px 圆角 —— 与「全局直角」规范冲突。
新写按钮时记得显式 `border-radius: 0`。

**给测试脚本的教训**：`matrix-full.mjs` 里的审计代码写在 **JS 模板字符串**内，
注释里出现反引号会直接把模板截断（报 `SyntaxError: Unexpected identifier`）。已在脚本内注明。

### F3. 新增的回归断言

`matrix-full.mjs` 的 settings 检查项增加 `fontSlider`：
格子数必须为 3 · **格子自身背景必须透明**（`alpha ≤ 0.5`，否则判定"挡住滑块"）·
滑块背景 `alpha > 0.5`（不可见即失败）· 选中格文字与滑块底色的对比度 ≥ 3。

最后两条正是 F2 那个坑的回归防线 —— 浅色正常、深色失效的问题不会再"静默通过"。

## G. 2026-09-29 三次：通知栏进度 + 默认深色主题

> 用户反馈：「通知栏下拉那个进度条 00:00-00:00 一直这样，解决一下」+「设置改成默认深色主题」

### G1. 通知栏进度一直 00:00-00:00（★ 根因是参数压根没传到原生）

**排查过程（先量数据再改）**：用合成数据直接调插件，然后读**系统侧**的真实状态：

```
adb shell dumpsys media_session
  → state=PlaybackState {state=PLAYING(3), position=0, buffered position=0, speed=1.0}
    metadata: size=7, description=HMANUAL 进度测试, 测试歌手, 测试专辑
```

标题/歌手传到了，**时长与位置却是 0** —— 说明 `show({duration: 211000})` 里的数字根本没进原生。

**根因**：Capacitor 的 `PluginCall.getLong()` 对 JS 数字（经桥变成 `Double`）**不做转换，直接返回 null**。
于是 `nextDuration != null && nextDuration > 0` 永远为假，`durationMs` 恒为 0 →
`METADATA_KEY_DURATION` = 0、`PlaybackState` 也只能给 `PLAYBACK_POSITION_UNKNOWN`。

**修复**（`MediaNotificationPlugin.java`）：

| 问题 | 修法 |
|---|---|
| `getLong` 拿不到数字 | 新增 `readLong(call, key, fallback)`：按 `Number` 取，兼容 `Integer`/`Double`/`String` 三种到达形态 |
| 位置恒为 `PLAYBACK_POSITION_UNKNOWN` | `updateNotification()` 里改用真实位置；时长未知时才退回 UNKNOWN |
| JS 侧从不推进度 | 新增 `setProgress` 插件方法 + JS 侧按秒级节流推送 |

**JS 侧（`mediaSession.js`）**：`watch([progress, time], () => pushProgress())`，节流「≥1s 且位移 ≥0.8s」。
单位换算要注意：store 里 `time`/`progress` 是**秒**，原生 `PlaybackState` 要**毫秒**；`track.dt` 本身就是毫秒。

**修复后实测**：
```
state=PlaybackState {state=PLAYING(3), position=150000, buffered position=211000, speed=1.0}
```
`150000`(2:30) / `211000`(3:31) —— 与推送值完全一致。

> 性能注意：`setProgress` 里**只在时长变化时**才重建 `MediaMetadata`（metadata 带位图，
> 每秒重建等于每秒新建一张 256×256 位图，既浪费又可能让系统侧反复刷封面）。

### G2. `hide()` 清不掉通知（顺带发现的真 bug）

**现象**：`hide()` 调了 `NotificationManager.cancel()`，但通知栏里的卡片依旧在。

**根因**：媒体卡片由**前台服务** `startForeground` 挂住，只 cancel 通知 id 是无效的 ——
服务还活着，系统会把它顶回来。`hide()` 里**从未停过服务**。

**修复**：
- `MediaNotificationPlugin.hide()`：先 `stopService(MediaPlaybackService)`，再 `cancel()`
- `MediaPlaybackService.onDestroy()`：显式 `stopForeground(STOP_FOREGROUND_REMOVE)`

**实测**：`hide()` 后 NotificationRecord 条数 **0**，`MediaPlaybackService` 已不在服务列表，
`isForeground` 消失。（修复前：服务仍在跑、`isForeground=true foregroundId=8801`，通知留着。）

### G3. 默认主题改为深色（★ 带一次性迁移）

`src/utils/theme.js`：`DEFAULT_THEME = 'dark'`。

**必须带迁移的原因**：老版本默认值是 `'system'`，而 `initTheme()` 会把
`getSavedTheme()` 的结果**写回 localStorage** —— 也就是说，即使用户从没进设置改过主题，
机器上也已经存着一个 `'system'`。**只改兜底值的话，已装过 App 的机器永远看不到变化。**

所以加了一次性迁移标记 `theme.default.migrated`：
只把「没存过」和「存的是老默认值 `system`」两种情况切成 `dark`；
用户显式选过的 `light` / `dark` 一律不动。

> `Settings.vue` 无需改动 —— 它在初始化时 `theme.value = getSavedTheme()`，自动跟随新默认值。
