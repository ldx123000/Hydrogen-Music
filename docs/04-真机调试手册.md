# 真机调试手册

> 本机没有可用模拟器（Hyper-V/WHPX Disabled、AEHD 驱动未装且需管理员）。
> **所有验证都靠真机 + adb 完成。** 本文是可以直接照抄的操作集合。

---

## 0. 前置

```bash
ADB=/c/android-sdk/platform-tools/adb.exe
NODE="/c/Users/<用户>/.workbuddy/binaries/node/versions/22.22.2-2/node.exe"
"$ADB" devices                 # 应看到 6afa2b6c  device product:garnet model:2312DRA50C
```

**装包并启动**：
```bash
"$ADB" shell input keyevent KEYCODE_WAKEUP     # 必须先唤醒屏幕！
"$ADB" shell svc power stayon true             # 保持常亮，否则 Node 会被挂起
"$ADB" install -r 'C:\Users\<用户>\Desktop\HydrogenMusic.apk'
"$ADB" shell am force-stop com.hydrogen.music
"$ADB" logcat -c
"$ADB" shell am start -n com.hydrogen.music/.MainActivity
sleep 70                                        # 首次要解压 4800+ 文件，慢，别急
```

> ⚠️ **手机熄屏后 App 进后台，Node 运行时会被系统挂起**
> （日志 `Capacitor: App paused` + `Not drawing due to screen off`），
> 极易误判成"插件没启动"。测试前一定要唤醒 + 保持常亮。

**正常启动应该长这样**：
```
[node][diag] os.tmpdir()=/tmp | TMPDIR=/data/user/0/com.hydrogen.music/cache | ...
[node] 临时目录已指向: /data/user/0/com.hydrogen.music/files
[node] 运行时启动中 (node v18.20.4)
[node] 网易云配置已就绪（anonymous_token / xeapi_public_key）
[node] 网易云 API 已就绪: http://127.0.0.1:36530
[node] 转发层已就绪: http://127.0.0.1:36531
```
日志 tag 是 `NodejsPlugin`；前端 `console.log` 走 `Capacitor/Console`
（但**需要 `loggingEnabled`，本项目未开，所以一般看不到**）。

## 1. 手段一：CDP 直连真机 WebView（最常用，最精确）

`capacitor.config.json` 已开 `webContentsDebuggingEnabled`，可以**在真机页面里跑 JS
并取回 DOM 几何数值**。判断"居中了没/被谁挡住了/元素多大"比截图可靠得多，
而且在模型读不了图片时是唯一可行方案。

```bash
PID=$("$ADB" shell pidof com.hydrogen.music | tr -d '\r')
"$ADB" forward --remove-all
"$ADB" forward tcp:9222 localabstract:webview_devtools_remote_$PID
curl -s http://127.0.0.1:9222/json | head -c 200      # 通了会返回 JSON

node scripts/mobile-test/device-cdp.cjs <表达式文件>
```

表达式文件里写 `(async () => { ... return JSON.stringify(...) })()`，返回值会被打印。

**可直接复用的测量脚本**（`scripts/mobile-test/`）：
| 文件 | 作用 |
|---|---|
| `eval-device-round3.js` | 进播放页 + 看那一行图标哪些被隐藏 + 右上角按钮的圆形高亮是否清掉 |
| `eval-device-round4.js` | 设置页 Windows 项是否隐藏 + 深色模式前后取色对比 |
| `eval-device-stack.js` | 播放页各行的垂直堆叠与是否溢出 |
| `eval-device-avatar.js` | 头像可点性（`elementFromPoint`）+ 点头像能否出面板 |
| `eval-device-wave-real.js` | 真实歌曲播放 + 波形是否在动 + `currentMusic` 的内部结构 |
| `eval-device-playing.js` | 读播放状态（最轻量，常用于验证动作是否生效） |
| `eval-device-find-song.js` | 在本地库里按关键字找歌 |

**两个必踩的测量陷阱**：
1. **全屏播放器开着时，量什么都是 0×0** —— 它会把 `.home` 设成 `display:none`，
   整条祖先链高度归零。**测量前先 `playerStore.widgetState = true` 关掉播放器**，
   否则会把正常状态误判成"改动造成的回归"。
2. **`ls` 默认不按时间排序** —— 验证产物新鲜度要用 `ls -lat`，否则会误判"构建没生效"。

## 2. 手段二：`uiautomator` 看 SystemUI（通知栏）

**通知栏属于 SystemUI，`uiautomator dump` 能看到它** —— 这是自动点击通知按钮的
唯一途径，也是复现用户真实操作的唯一方法。

```bash
"$ADB" shell cmd statusbar expand-notifications
sleep 3
"$ADB" shell uiautomator dump /sdcard/ui.xml
"$ADB" pull /sdcard/ui.xml 'C:\hydrogen-build\ui.xml'     # 注意：adb 是 Windows 程序，
                                                           # 目标路径要写 Windows 形式
# 从 xml 里正则取按钮 bounds，算中心坐标，然后……
"$ADB" shell input tap <x> <y>
```

> ⚠️ 通知栏会**自动收起**，所以 dump 和 tap 要写在**同一条命令**里。
> 另外 tap 用的是**物理像素**（= CSS 坐标 × dpr；本机 dpr=3，视口 406×904）。

实际用到的 Python 片段（从 xml 取坐标）：
```python
import re
s = open(r'C:\hydrogen-build\ui.xml', encoding='utf-8').read()
for n in ['暂停','播放']:
    m = re.search(r'content-desc="'+n+r'"[^>]*bounds="\[(\d+),(\d+)\]\[(\d+),(\d+)\]"', s)
    if m:
        x1,y1,x2,y2 = map(int, m.groups())
        print((x1+x2)//2, (y1+y2)//2); break
```

**通知栏相关的 dumpsys**：
```bash
"$ADB" shell dumpsys notification --noredact | grep -A 10 com.hydrogen.music
# 应看到：category=transport  actions=N  flags=...|ONGOING_EVENT|...（前台服务还会多 FOREGROUND_SERVICE）

"$ADB" shell dumpsys activity services com.hydrogen.music
# 应看到：MediaPlaybackService  isForeground=true  foregroundId=8801  types=0x00000002
```

## 3. 手段三：媒体键（注意！这条路和通知栏按钮不是一回事）

```bash
"$ADB" shell input keyevent 127     # KEYCODE_MEDIA_PAUSE
```

**关键教训**：媒体键走 `MediaSession.Callback.onMediaButtonEvent()`，
**通知栏按钮走 `MediaController.transportControls()`** —— 两条不同的路。
**只测媒体键会得出"链路正常"的错误结论**（本项目就因此白白多排查了一轮）。

排查通知栏问题时，**必须用第 2 节的方法点真的按钮**。

## 4. 原生日志 vs console.log

| 通道 | 是否需要开关 | 用途 |
|---|---|---|
| `System.out.println`（Java） | 不需要，一定进 logcat | **排查首选**，在链路每一环打点 |
| `console.log`（WebView） | 需要 Capacitor 的 `loggingEnabled`（**本项目未开**） | 看不到，别指望 |
| `Capacitor/Plugin` 的 `V` 日志 | 默认有 | 能看到"哪个插件方法被调用" |
| 系统 UI 日志 | 默认有 | `MediaNotificationController: onMediaDataLoaded ... token=MediaSession$Token@...` |

```bash
"$ADB" logcat -d | grep -a "MediaNotification"          # 插件日志
"$ADB" logcat -d | grep -a "MediaSessionService|onSessionPlaybackStateChanged"
"$ADB" logcat -d | grep -a "FATAL|AndroidRuntime"       # 崩溃
```
> 用 `grep -a`（logcat 有二进制内容，不加 `-a` 会被当二进制文件跳过）。

## 6. 浏览器里跑「手机浏览器形态」（调 UI 最快）

```bash
node node_modules/vite/bin/vite.js build          # 先构建前端

# 然后浏览器开 http://127.0.0.1:8080
```

配合 `scripts/mobile-test/cdp.cjs <url> <输出图名> [注入脚本]`（系统 Edge，390×844 触摸视口）
可以做快速迭代。

> 涉及登录态的验证只能真机。

## 8. 三个最容易误判的地方（务必记住）

1. **"点了没反应" ≠ 元素不存在** —— 十有八九是命中测试被挡。
   合成 `dispatchEvent` 会绕过命中测试，手写 click 能成功、真机手指点却没反应，
   就是这类问题。用 `elementFromPoint` 或 `input tap` 验证。
2. **"PC 上正常" ≠ "手机正常"** —— 8 个坑 PC 一个都不触发。
3. **杀进程重启后再看日志** —— `logcat -c` 清一下再复现，避免被旧日志误导。
