# 网易云双人一起听

入口：播放条或全屏播放器的耳机按钮，也可以使用右上角头像菜单 → 一起听。功能会在当前播放区域内展开，不使用独立弹窗。

## 已实现

- 创建、加入、退出官方双人房间；恢复账号已有房间，同账号应用重启后尝试恢复之前的连接。
- 双向切歌、播放、暂停、进度同步；从 `sync/playlist/get` 接收 `playCommand`，使用服务端 `serverSeq` 校正固定进度锚点。
- 共享队列读取；歌曲的添加、删除和切换统一使用播放器原有的播放列表，并自动同步列表循环、单曲循环和随机顺序。
- 建房前可从关注列表选择好友并发送网易云站内邀请；加入房间后不再显示邀请控件。
- 成员列表、本次连接时长、本次听过记录、错误展示、手动重新同步。
- 请求串行化、自己指令回声过滤、旧快照保护、音频加载保护、断线指数退避、服务端心跳间隔、账号切换清理。
- 自然播完由房间创建者优先推进，避免两个 Hydrogen 端同时下一首；房间期间关闭提前无缝切歌，单曲循环沿用音频后端。

加入/恢复会替换本机播放列表并跟随房间。创建新房间会共享当前可用网易云队列。只有普通网易云歌曲可以共享，本地、电台、云盘私有歌曲和其他来源不会转发；权限仍由各自账号决定。退出调用上游结束接口，可能结束整个房间。

## 实现与验证边界

这不是“官方全部功能已完成”的声明：

- 当前是双人房间，明确拒绝官方 `multishare` 多人房间链接；多人房间是不同协议。
- 未实现官方语音聊天、表情互动、距离、累计一起听时长、聊天室及多人推歌/置顶。
- 双向接收采用 HTTP 轮询，正常间隔 2 秒，加上网络和加载耗时；不是官方即时推送通道。
- 邀请短链接需要先取得完整 `st.music.163.com/listen-together/share/` 链接。
- 加载歌曲最多等待 15 秒，失败后显示错误并重试；无法播放的歌曲不会绕过权限。
- 两端同时编辑整个队列时仍受官方版本合并行为影响，需要线上验证。
- 本次连接时长与历史是本机会话信息，不冒充官方累计数据。

`node --test tests/listenTogether.test.mjs`（Node 22.7+）检查双向命令、固定锚点、重复回声、并发、队列版本向量、心跳节流、重连与清理。`npm run build` 检查 Vue 构建。

已用隔离模拟接口配合实际 Pinia/Vue/播放器适配验证好友暂停到 60 秒、好友从 30 秒播放，以及本地暂停回传且无重复上报。没有用真实账号建房或向真实好友发消息。仍需两个网易云账号验证官方客户端互通、切歌权限、多人并发操作与退出行为。

## 协议依据

- 项目依赖 `@neteasecloudmusicapienhanced/api` 的 `module/listentogether_*.js`、`module/api.js` 与官方 API 示例。
- https://github.com/Binaryify/NeteaseCloudMusicApi/issues/1676
- https://github.com/lakyTao/splayer-together-plugin 提供的协议字段与实测说明（`playCommand`、`serverSeq`、`PROGRESS`、心跳 `timeSpan`、版本向量）；本项目独立实现状态机，未复制其插件实现。

列表上报使用依赖现有的通用 `/api` 入口，以保留 `playMode` 和所有参与者的版本向量；旧列表包装器会丢弃这些字段。登录 Cookie 继续走项目原有请求和 IPC 链路。
