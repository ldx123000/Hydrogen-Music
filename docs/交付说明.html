一、安装须知

  1. 把 HydrogenMusic.apk 传到手机，点击安装。系统会提示「未知来源应用」，允许即可。
  2. 必须是 debug 签名，安装时若提示「签名不一致」，需先卸载旧版再装。

① 不要运行 npx cap sync —— 本项目依赖"生成物常驻构建目录"，sync 会破坏它。
② 构建路径必须纯 ASCII，务必走 run-full-build.sh，不要手动复制源码。

4.1 移动端统一适配方案（核心决策）

不逐机型微调，而是把布局视口锁死为设计宽 390，WebView 按屏幕宽等比缩放：

位置做法
index.html<meta name="viewport" content="width=390, viewport-fit=cover, user-scalable=no">
MainActivity.javasetUseWideViewPort(true) + setLoadWithOverviewMode(true) + 禁缩放 + setTextZoom(100)
mobile.csstext-size-adjust: 100%（字体免疫系统缩放）

收益：320～430dp 全机型渲染同一套布局，任何机型都不会错位/溢出。
代价：窄屏整页等比缩小、宽屏放大，字号绝对大小在不同手机上略有差异。这是该方案的固有取舍。

五、本轮改动摘要

完整清单见 02-改动清单.md（A–G 节）。按问题归类：

5.1 登录态丢失（A 节 / D2）

根因不是 cookie 存储，而是两条"误清登录态"的路径：

  • request.js：任何请求（含没带 MUSIC_U 的匿名请求）收到 301/401/403 都触发全局登出
  • accountSession.js：启动水合失败（冷启动 Node 未就绪、请求超时）也清空登录态

已分别加守卫 shouldTriggerAutoLogout() / isAuthError()，只有"确实带了登录 cookie 仍被拒绝"才清理。

5.2 移动端 UI 缺陷（E 节）

问题根因（真机实测）
「每日推荐」跳进「我的」路由挂在 /mymusic/playlist/rec 下 → 提升为顶层 /recommend，新增页内返回按钮，Tab 归「首页」高亮
漫游页 MODE 按钮压住标题按钮 x 213..363/y 77..105 与徽标 x 132..258/y 81..107 正面重叠 → 标题下移 30px

5.3 歌词字体大小改为三档滑轨（F 节）

由下拉菜单改为「小 / 中 / 大」滑轨控件，一次点击直达。美术规范沿用同页既有控件： 直角无圆角 · 轨道底色 rgba(255,255,255,.35) · 选中态纯黑填充+白字 · 13px 思源黑体 Bold · 高 34px。

踩坑记录：第一版格子用 <button>，被 theme.css 的全局规则 .dark button { background-color:#2a2e34 !important } 刷成不透明深色， 盖住了底下的滑块 —— 浅色正常、深色下完全看不出选中哪一格。 改用 <div>（本页同类控件本来就都是 div）解决。 另：reset.css 未重置 border-radius，<button> 会带 UA 的 2px 圆角，与"全局直角"规范冲突。

5.4 通知栏进度一直显示 00:00-00:00（G 节）

根因：Capacitor 的 PluginCall.getLong() 对 JS 数字（经桥是 Double）不做转换、直接返回 null —— 于是 show({duration}) 里的时长根本没进原生，METADATA_KEY_DURATION 与 PlaybackState 全是 0。

用 adb shell dumpsys media_session 实测确认（修复前 position=0, buffered position=0）。

  • 新增 readLong()：按 Number 取参，兼容 Integer/Double/String
  • 新增 setProgress 插件方法 + JS 侧按秒级节流推送进度（store 里是秒，原生要毫秒）
  • PlaybackState 不再用 PLAYBACK_POSITION_UNKNOWN

修复后实测：position=150000(2:30) / buffered=211000(3:31)，与推送值一致。

顺带修掉一个真 bug：hide() 只 cancel() 通知、从不停前台服务， 导致清空播放列表后通知一直赖着。已改为先 stopService 再 cancel， 并给服务 onDestroy 补 stopForeground(STOP_FOREGROUND_REMOVE)。

5.5 默认深色主题（G 节）

默认主题由 system 改为 dark，并附带一次性迁移。

为什么必须迁移：老版本默认值是 system，而启动时会把 getSavedTheme() 的结果写回 localStorage —— 即使用户从没改过主题， 机器上也早存着 system。只改兜底值的话，已装过 App 的机器永远看不到变化。
迁移标记 theme.default.migrated：只把"没存过"和"存的是老默认值 system"切成 dark； 用户显式选过的 light/dark 一律不动。

5.6 整页可横向拖动导致两侧被切（G 节）

现象：云盘等页面在部分手机上出现"左边被切、右边也被切"的错位。

根因：不少浮层用「绝对定位 + 负 right」做滑入（云盘的编辑面板是 .file-edit { right: -140px }），把 .home-content（overflow:auto） 撑出一段横向滚动范围，整页可以被横向带动。

为什么常规检查发现不了：横向溢出被 .home-content 吸收， documentElement.scrollWidth 完全正常 —— 必须单独量内容区。

修复：让 .file-container 裁掉它（保留滑入动画），并给移动端的 .home-content 加 overflow-x: hidden，一次性掐掉这一类问题。实测修复后横向可滚动量 126px → 0。

关于测试脚本自身的坑：低对比度检测最初用 el.textContent 取文字， 会把"父容器的继承 color"当成实际文字色，误报 div.toggle 对比度 1.12。 修正为只取元素自身的直接文本节点后，真页面 0 误报、且注入的白底白字探针能被准确检出。
教训：测试脚本本身也需要被验证，否则会把工具缺陷当成产品缺陷去"修"，越修越乱。
