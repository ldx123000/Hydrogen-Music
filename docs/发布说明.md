## 二、构建环境

| 组件 | 版本 / 位置 | 说明 |
|---|---|---|
| Node.js | 18 或更高 | 跑构建脚本 |
| JDK | 21 | 可用 `JAVA_HOME` 覆盖 |
| Android SDK | 需要 `android-36` 平台 + build-tools | 本机在 `C:\android-sdk` |
| Gradle 缓存 | `C:\hydrogen-gradle` | 可用 `GRADLE_USER_HOME` 覆盖 |

### 构建步骤

```bash
# 1. 安装依赖
npm install
cd mobile-runtime && npm install && cd ..

# 2. 一键构建（vite build + 注入 Node 运行时 + gradle assembleDebug）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-android.ps1

# 3. 安装到设备
adb install -r HydrogenMusic.apk
```

### 常用参数

```bash
# 只做环境检查，不构建
... -CheckOnly

# 深度清理后构建（多次构建后建议执行，见第五节）
... -Clean

# 跳过源码镜像（构建目录已是最新时）
... -SkipSync
```

## 三、产物构成

APK 约 209 MB，构成如下：

| 部分 | 大小 | 说明 |
|---|---|---|
| `lib/` | 147.6 MB | 内嵌 Node 运行时的三个 CPU 架构 |
| └ `x86_64` | 53.5 MB | **仅模拟器需要**，删掉可省 53.5 MB |
| └ `arm64-v8a` | 49.1 MB | 主流真机 |
| └ `armeabi-v7a` | 45.0 MB | 老款 32 位机型 |
| `assets/` | 46.5 MB | Node 运行时脚本 36.3 + 前端产物 10.1 |
| `classes.dex` | 8.0 MB | Java/Kotlin 代码 |
| 其余 | ~0.5 MB | 资源、清单等 |

**减小体积的可选方案**：在 `android/app/build.gradle` 里限定 ABI：

```gradle
ndk {
    abiFilters 'arm64-v8a', 'armeabi-v7a'   // 去掉 x86_64
}
```

或使用 App Bundle（AAB）让商店按设备下发对应架构。

## 四、技术架构概要

```
WebView（页面 https://localhost）
  Vue 3 前端  ←─ Capacitor Bridge ─→  Java 插件
                    ↕
         Capacitor 本地服务器（同源 https，可流式读 content://）
                    ↕
        SAF / MediaStore / ContentResolver
```

关键点：

1. **前端零改动** —— 通过 `src/utils/webBridge.js` 把 Electron 的 `windowApi.*` 在安卓上重新实现
2. **本地播放靠 Capacitor 内置代理** —— `content://` 换成 `https://localhost/_capacitor_content_/…`，
   绕开 WebView「https 页面禁止加载 content:// / file://」的限制
3. **文件访问走 MediaStore** —— 安卓 10+ 分区存储下不按路径读写；下载与扫描共用同一份数据
4. **原生能力由 Java 插件提供** —— 本地扫描/封面/歌词、下载+ID3 标签、通知栏、返回键

## 五、构建注意事项

### 5.1 为什么需要 `-Clean`

`vite` 的 `emptyOutDir` 在构建时被关闭（`HM_KEEP_DIST=1`）。原因是一次性删除几千个
构建产物会触发沙箱的批量删除保护、导致构建中断；而增量清理又设了每轮 40 个文件的上限，
**永远追不上新增速度**。实测未清理时 `dist/` 会堆到 **2700+ 个重复文件（约 86 MB）**，
并全部打进 APK。

`-Clean` 在构建前一次性清空：

```
dist/
android/app/src/main/assets/public/assets/     ← 保留 nodejs 运行时
```

实测清理后：前端文件 **2724 → 86 个**，且构建变得可复现（同一源码两次构建 md5 一致）。

### 5.2 不使用 `cap sync`

本项目**刻意不走 Capacitor CLI 的 copy/update**（它会整体删除 `assets/public`，同样触发删除保护，
并且会重新生成 `capacitor.settings.gradle`、覆盖 `capacitor.plugins.json`）。
构建脚本改为增量复制 + 打补丁的方式，见 `scripts/build-android.cjs`。

### 5.3 路径中的中文

`build-android.ps1` 检测到工作目录含非 ASCII 字符时，会先通过 `scripts/sync-to-build.cjs`
把源码镜像到纯 ASCII 构建目录（默认 `C:\hydrogen-build`）—— 因为 Android Gradle Plugin
拒绝 CJK 路径。

## 六、已知问题

| 问题 | 影响 | 说明 |
|---|---|---|
| **跨设备布局差异** | 中 | 项目里有 249 处 `vw/vh`（桌面端当等比缩放用）。不同屏幕宽度下比例会变，**这是屏幕尺寸差异，不是渲染引擎差异**，打包浏览器内核无法解决。可行解法：把 `vw` 基准改为标准设计宽度（`--hm-vw: calc(100vw / 406)`） |
| **移动端判定边界** | 低 | `(max-width: 900px), (pointer: coarse) and (max-width: 1024px)`；平板/横屏/宽视口可能误走桌面分支 |
| **暂停不是断点续传** | 低 | 下载暂停目前是「原地等待」，未实现 HTTP Range 续传 |
| **首次启动较慢** | 低 | 需解压约 4800 个内嵌运行时文件，40～60 秒，期间白屏属正常 |

完整待办见 `docs/03-待办与已知问题.md`。

## 七、验证方式

### 7.1 真机调试（CDP over adb）

```bash
adb forward tcp:9222 localabstract:webview_devtools_remote_$(adb shell pidof com.hydrogen.music)
node tools/device-debug/device-cdp.cjs <表达式文件>
```

`tools/device-debug/` 下有 35 个可复用脚本，包括：

| 脚本 | 用途 |
|---|---|
| `device-cdp.cjs` | 在设备 WebView 里执行一段表达式 |
| `cdp.cjs` | 通用 CDP 连接与求值 |
| `eval-device-*.js` | 各页面（首页/播放页/设置/云盘等）的状态探查 |
| `setup-*.js` | 构造测试场景（播放列表、本地目录等） |
| `device-health.ps1` | 设备健康检查（只读） |

### 7.2 UI 矩阵测试

`ui-matrix/` 目录（在交接包中）使用 `tools/matrix-full.mjs` 在多种视口宽度下批量截图并检查
溢出/对比度。本仓库保留了脚本，截图结果未纳入版本库。
