### 修复 6（通知栏）—— 必须走原生，已完整实现并真机验证
**真机探测结论**：Android 16 WebView **完全没有** `navigator.mediaSession`、
`MediaMetadata`、`Notification`（全是 undefined）。所以 Web 标准那条路在 App 里是死的，
**通知栏只能靠原生代码**（我原先"把 initMediaSession 接上"是空操作，好在真机测出来了）。

新增 `android/app/src/main/java/com/hydrogen/music/MediaNotificationPlugin.java`：
- **只用框架自带 API**（`Notification.MediaStyle` + `android.media.session.MediaSession`），
  **不引入 androidx.media** —— 因为本项目不跑 `cap sync`，加依赖会很麻烦。
- 导出 `show({title,artist,album,coverUrl,playing})` / `setPlaying({playing})` / `hide()`。
- 通知按钮用**运行时注册**的 `BroadcastReceiver`（`RECEIVER_NOT_EXPORTED`，API 33+）

## ★ 最终定位：通知栏按钮点不动 = `mediaId` 为 null（MIUI 专属）

# 从 xml 里正则取 content-desc="暂停" 的 bounds，算出中心坐标

只测媒体键会得出"链路正常"的错误结论。**必须点真的按钮。**

### 逐层加探针，定位断点
在原生 `emit()` 里加 `System.out.println`（原生日志一定进 logcat；而
`console.log` 需要 Capacitor 的 `loggingEnabled`，本项目没开，所以看不到）。
- 点通知栏按钮 → **原生探针零输出** → 回调根本没被调用（不是 JS 侧的问题）
- 而媒体键 → 探针正常输出 → 说明 MediaSession 本身是好的

### 根因与修法
`dumpsys` / MIUI 日志里的 MediaData 显示 **`mediaId=null`、`mediaDuration=0`**。
MIUI 的媒体卡片在 `mediaId` 为空时无法给按钮接线（同时它的灵动岛代码还会抛
`NullPointerException: null receiver`）。补上两样即修复：

1. **`MediaMetadata.METADATA_KEY_MEDIA_ID`** ← 关键，必须有值
2. `MediaMetadata.METADATA_KEY_DURATION`

前端 `show()` 调用相应多传 `mediaId`（曲目 id）与 `duration`（`track.dt`）。

修后实测（真机点通知栏「暂停」）：
```
mediaId=5257138, mediaDuration=0
System.out: [MediaNotification] 收到动作 -> pause     ← 回调触发
Capacitor: Notifying listeners for event mediaAction  ← 送到 JS
```

### 顺带修掉的两处
- **大图标必须是 Bitmap**：只给资源 id 时 MIUI 会拿到 `Icon(typ=RESOURCE)`。
  改为拿不到封面就把应用图标绘成 Bitmap 兜底。实测 artwork 由 `RESOURCE` → `BITMAP size=256x256`。
- **前台服务不再跟随 `playing`**（详见上一节）。

### 教训
1. **别只用 keyevent 验证通知栏**——媒体键和通知栏按钮是两条路。
2. **`uiautomator dump` 能看到 SystemUI 的通知栏**，是自动点击通知按钮的唯一途径。
3. 原生日志（`System.out`）比 `console.log` 可靠：后者要 `loggingEnabled` 才进 logcat。
4. MIUI 的媒体卡片对 `mediaId` 有强依赖，第三方播放器接 MIUI 时必须提供。
